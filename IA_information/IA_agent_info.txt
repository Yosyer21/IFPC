## 5. CORE LOGIC
- matching: score 0-100 = requisitos del club (posición, edad, nivel, geografía) vs perfil del jugador; guardar score + explicación por criterio
- video: upload S3 -> worker transcodifica -> thumbnail/preview -> estado {uploading,processing,ready,failed}
- membresías: tiers (free/premium/scout/club) vía Stripe; expiración en worker
- reclutamiento flujo: submission -> trial -> negotiation -> contract (estados por etapa)
- notifications: in-app + email; tipos: application, match, trial, negotiation, contract, payment, reminder

## 17. PGLITE (PostgreSQL embebido en WASM — sin Docker/Postgres externo)
- `pglite-prisma-adapter` + `@electric-sql/pglite` en packages/database; PrismaClient usa el adapter cuando `USE_PGLITE=true` (por defecto)
- `pnpm db:setup-pglite` → genera SQL del esquema (prisma migrate diff), lo aplica en `.pglite/` y ejecuta el seed (idempotente)
- Config: `.env` (root) y `apps/web/.env.local` con USE_PGLITE=true, PGLITE_DIR absoluto, AUTH_SECRET generado
- next.config: `serverExternalPackages` para pglite (carga WASM en runtime Node)
- Scripts con `node --env-file=.env --import=tsx`; process.exit(0) para evitar cuelgues (PGlite mantiene el event loop)
- IMPORTANTE: los scripts que modifican la BD (seed, create-admin) deben ejecutarse con el servidor detenido y reiniciarlo después (PGlite mantiene estado en memoria por proceso)
- Para usar Postgres real/Docker: `USE_PGLITE=false` y volver a `pnpm db:migrate`
- Verificado en local: login de 6 roles + ~27 rutas del dashboard responden 200 con datos del seed
